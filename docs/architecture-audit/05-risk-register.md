# Risk Register

| Architectural risk | Why it matters | Mitigation | Test coverage needed |
| --- | --- | --- | --- |
| Legacy/global authoring deletions break the only proof that removed routes stay removed | The contract depends on absence guarantees, not just new happy paths | Freeze negative contract tests before deleting code and keep absence assertions where the missing surface is itself the shipped contract | `backend/tests/test_legacy_backend_cutover.py`, `backend/tests/test_workflow_package_removed_contract_gates.py`, `frontend/src/routes.test.tsx`, `frontend/e2e/navigation.spec.ts` |
| Startup repair cleanup removes logic still needed for live tables | DB init is the schema authority; over-deletion could strand current installs | Split live repair from retired-surface cleanup and delete retired logic only after route/table absence checks and focused upgrade-test updates | `backend/tests/test_runtime_db_upgrades.py`, `backend/tests/test_workflow_package_db_upgrades.py` |
| Export trust-boundary cleanup leaks or preserves secret-adjacent MCP fields incorrectly | GAP-003 is a security/contract issue with round-trip implications | Decide the export contract once, then update backend export tests and frontend preview tests to one clean rule | `backend/tests/test_workflow_package_export.py`, `backend/tests/test_workflow_package_export_security.py`, `frontend/src/pages/workflow-packages/preflight-launch-export.test.tsx` |
| Runtime finalization changes introduce lease/race regressions | GAP-004 touches heartbeats, stale recovery, and terminal writes | Investigate first, then change one ownership path with targeted contract tests instead of speculative rewrites | `backend/tests/test_workflow_package_runtime_api.py`, `backend/tests/test_workflow_package_run_contracts.py`, `backend/tests/test_runtime_repositories.py` |
| Frontend cleanup reintroduces removed routes or hidden nav entries | Route/nav removal is part of the shipped contract | Keep route metadata and router tests as first-class guards while renaming package-local types and cleaning authoring UI | `frontend/src/routes.test.tsx`, `frontend/e2e/navigation.spec.ts`, `frontend/e2e/shell-regression.spec.ts` |
| Lease/finalization ownership is unclear and a speculative fix could introduce races | GAP-004 is a precision issue, not proven bug evidence; overreach could destabilize execution | Require an investigation gate inside S06; only collapse ownership if targeted tests prove a real failure mode | `backend/tests/test_workflow_package_runtime_api.py`, `test_workflow_package_run_contracts.py`, `test_runtime_repositories.py`, `test_workflow_package_runtime_artifacts.py` |
| Package manifest cleanup could preserve or accidentally re-enable global authoring semantics | Legacy frontend/backend names still imply standalone roots | Remove legacy names and parser branches in one clean cut and keep invalid global roots invalid in parser tests | `backend/tests/test_workflow_package_manifest_parser.py`, `test_workflow_package_manifest_compiler.py`, `test_workflow_package_manifest_decompiler.py`, workflow-package frontend tests |
| Secret-safe read guarantees could regress during model-connection or export cleanup | A single echoed field or preview leak breaks a core trust boundary | Keep encrypted persistence and write-only reads invariant; separate export-contract decisions from model-connection secret handling | `backend/tests/test_runtime_repositories.py`, `test_workflow_package_export.py`, `test_workflow_package_export_security.py`, model-connections frontend tests |
| Tool catalog and runtime dispatch could drift apart after separation | Users could see tools they cannot run, or runtime tools could bypass grants/extension state | Freeze catalog contract tests first, then move runtime dispatch behind the same grant/filter checks | `backend/tests/test_tool_catalog_api.py`, `test_runtime_tools.py`, `test_extension_lifecycle_matrix.py`, `test_mcp_runtime.py` |
| Memory cleanup could accidentally widen access or break explicit-scope UX | Memory is a platform-core boundary with strict scope/grant rules | Keep access-context and concrete private scope mandatory; keep `/memory` single-route and inline only | `backend/tests/test_api_memory.py`, `test_memory_service.py`, `test_memory_domain_schemas.py`, `test_memory_layer_static_contracts.py`, `frontend/e2e/memory.spec.ts` |
| Extension isolation cleanup could leak finance assumptions into core or add Digital Oracle surface area | That would violate the bundled-extension ownership model | Keep `/api/extensions` slim, preserve Finance state gates, and reject any Digital Oracle route/nav additions | `backend/tests/test_extensions_api.py`, `test_extension_registry.py`, `test_extension_lifecycle_matrix.py`, `frontend/src/routes.test.tsx`, `frontend/e2e/extensions.spec.ts` |
| Frontend package-local renames could leave hidden compatibility imports or dead nav entries | The UI may appear clean while stale helpers or metadata preserve removed routes | Rename and delete in one clean sweep with route/nav tests locked first | `frontend/src/routes.test.tsx`, `frontend/e2e/navigation.spec.ts`, `frontend/e2e/shell-regression.spec.ts`, `frontend/e2e/workflow-packages.spec.ts` |
| Full-stack cleanup could leave stale docs/tests that still imply old contracts | Documentation bias can preserve dead paths after code is cleaned | End with a docs/test sweep that deletes stale compatibility wording and redundant fixtures rather than documenting exceptions | Full backend suite, full frontend suite, `frontend/e2e/*`, `docs/architecture-audit/*`, live owner docs under `docs/*.md` |
| Persistence cleanup can run before route/module cleanup has actually removed all imports of retired surfaces | Startup repair or model exports may still reference code slated for deletion, causing boot/import failures | Keep S13 blocked on S01, S02, S03, and S11 verification; require mypy plus upgrade tests before deleting retired repair/model code | `backend/tests/test_runtime_db_upgrades.py`, `backend/tests/test_legacy_backend_cutover.py`, `backend/tests/test_runtime_models.py`, `cd backend && uv run mypy app` |
